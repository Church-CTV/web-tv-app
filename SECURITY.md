# Security policy

Never put credentials, signing material, private endpoints, personal information
or exploit-ready production details in a public issue or pull request.

Use the repository's private vulnerability-reporting form when enabled. If it is
unavailable, contact an organization owner privately to arrange a secure channel
before sending details. Do not send secrets in issue attachments or public gists.

Include the repository/version, a minimal synthetic reproduction and impact.
Never test against production without explicit authorization. No supported
release or response-time SLA is advertised yet. Scanner passes are not security
guarantees. Removing a file is not revocation of a compromised credential.
